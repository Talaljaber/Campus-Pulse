## Deviations and notes

- `NewAnnouncement` lives in `domain/announcements.py` (not the use-case module) because `test_architecture` lets routes import only composition, DTOs, config and domain.
- `create(actor, cmd, created_by)` takes the caller's Supabase user id as a third argument (the `Actor` protocol has no user id); the route passes `caller.user_id`.
- `AnnouncementsUseCase` takes `offices: Collection[str]`; composition passes `OfficeMap.offices`.
- The header shows the display name (fallback alias) on the pages this package owns (Home, Profile, Staff Announcements, Accounts). The other screens (Ask, Staff queue, Corrections, Incidents, Reports, Outbox) still pass only `alias`; I did not touch them to avoid conflicts with P9.6 and because their `alias` prop also drives Realtime. Integrator or a later package: pass `name={nameOf(profile)}` where `profile` is available.
- No `/requests` change (P9.7). No `domain/journey.py`, `journey_ports.py`, staff queue or ticket pages touched.
- Merge hot spots (all additive): `api_contract.py` (appended after `admin_reindex`), `mock_app.py` (appended routes), `dto.py` (appended), `composition/api.py` and `composition/online.py` (one field and one wiring line each), `fastapi_app.py` (one router), `allowlist.ts` (appended rules), `openapi.json`, `types.gen.ts`, `docs/api/endpoints.md` (regenerate after merging).
