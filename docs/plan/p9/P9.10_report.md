## Decisions and deviations
1. Order of operations for a message with files: upload first (unattached rows), then the comment with `file_ids`. This was needed so the email can say "N file(s) attached"; `activity_id` on the upload route still works (it must be a message of the same caller and visibility). A failed comment can leave unattached files (they show under "Files not in a message" and count against the caps); retrying the same message does not upload them twice.
2. Column-level `grant select` on `ticket_files` for `authenticated` (no `storage_path`, no `uploader_alias`) instead of a table-wide grant. The web never needs the path.
3. A filename or declared content type that disagrees with the bytes is a 422 ("renamed .exe or .html as .png"). Valid UTF-8 text without NUL (including HTML) is accepted as `text/plain` and is only ever served as a download. Images and PDFs open in a tab; every other type gets `&download=<file id>.<ext>` on the signed link.
4. Internal and public file visibility must match the message: an internal file only joins an internal note.
5. Requester requesting a link for an internal file: 403 (not 404).
6. No Realtime for `ticket_files` (not added to the publication); the web re-reads the list after a send.
7. `build_lifecycle` test helper got a `files` argument; `test_dto_contract.py` now builds multipart calls from any fixture that has `files`.
8. Proxy multipart tests live in `lib/__tests__/proxy-files.test.ts` with `@vitest-environment node` (jsdom's File does not survive a Request body).
9. Out of scope, as asked: **no virus scanning**; the model never reads file contents; emails carry no attachments.
10. Storage objects are NOT removed when a ticket is deleted: the FK cascade only removes the `ticket_files` rows (documented in the migration).
