# P9.7 report: My Requests and requester actions (web only)

Branch `p9/P9.7`, based on `ce7dac1`. No Python, Supabase, model or docs-index changes.

## What changed

- `/requests` (`MyRequestsScreen`): DataTable of the viewer's own tickets (Ticket # | Title | Department | Status | Last update | We aim to reply by), FilterGroup status active / finished / all (default active), demo line "Demo: no real department is contacted.", row click and Enter open `/requests/[id]`. Works for students and staff.
- `/requests/[id]` (`RequestScreen`): request text, department and status badges, `TicketThread viewer="requester"`, `RequesterReply` (internal false, no status; hint "Sending a message reopens your request." on solved/closed), `StudentActions` (Solved / Close / Keep open, shown when the ticket is solved or `awaiting_student` on new/in_progress/solved; disabled while posting; toast on success, server message on 422). Not the caller's own ticket: "not found". Realtime on ticket and activity.
- Hooks: `useMyRequests(alias)` (reads own tickets, filters again by alias client-side, last update from the newest visible thread row, live inserts/updates), `useMyTicket(id, alias)` (own-ticket counterpart of `useTicketThread`, reuses `mergeActivity`).
- `lib/tickets/requester.ts` (`showStudentActions`, `messageReopens`, `matchesMyFilter`), `StudentActionRequest` in `types.ts`, `postStudentAction` in `service.ts`, repo `listMyTickets` and `listLastActivity`.
- Allow-list: `POST tickets/{id}/student-action`.
- i18n EN + AR: new group `myRequests` (before `advisor`) and `corrections.waitingSection`.
- RESTORE: `/staff/reviews` (`AdvisorScreen`) renders `useReviewQueue` + `ReviewQueue` / `CorrectionForm` as the first section "Waiting for review" (confirm and correct post `feedback`, memory toast, error toast; a `review_assigned` notice reloads it), above the advisor tabs, the flags and "Past corrections".

## Deviations and decisions

- The ticket table has no `updated_at`; "Last update" is the newest visible `ticket_activity` row, falling back to the newest of created, clock start, resolved. A live ticket update sets it to "now".
- Answer buttons are hidden on closed and merged tickets even if `awaiting_student` is set (the server would answer 422); the plan text only says `awaiting_student || solved`.
- The deadline column shows "-" for finished tickets (the clock is stopped).
- i18n key is `myRequests.demo`, not `demo.noRealContact`, to avoid colliding with P9.5's i18n edits.
- No e2e added: `student-basic` does not cover this area, and the review-queue e2e was not restored (the fake mock has no `review_queue` rows; not cheap). The corrections page e2e still passes with the new section.
