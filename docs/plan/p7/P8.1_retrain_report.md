## 6. How the lead scores the holdout (once, all candidates and modes in one sitting)

```
python scripts/score_holdout.py --model-dir .tmp/rc5/C0 --mode offline --holdout C:\Users\hp\Desktop\campuspulse_locked\locked_holdout.csv
python scripts/score_holdout.py --model-dir .tmp/rc5/C0 --mode llm     --holdout <same>
(same for C1 and C2)
```

The script first checks the file's sha256 against `bdfee810ef38d5c06018254e37b630e07c34d0b801c15455126be6399b2a4614`
(SELECTION.md) and exits 2 without reading a row if it differs; then runs `predict.py --debug` (`--use-llm` for
`llm`, scratch cache beside the model dir) and prints category and priority macro-F1 and accuracy per language and
pooled, the score 0.7 x category + 0.3 x priority (pooled) and the auto / ask / review shares. It prints only
aggregates. `--mode llm` needs `OPENROUTER_API_KEY` (read from `.env` or the environment). SELECTION.md says the
offline configuration decides the score; the `llm` run is extra information. SELECTION.md itself is not on `main`
yet (it exists only in another worktree), so the script carries the hash as a constant.
