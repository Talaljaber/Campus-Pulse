## Package 1: `llm_cue` raise-only floor (LLM flow only)

Rule (`config/llm_frontend.yaml`, `cue_floor`), from the P8.5 cues, any one of:
`physical_danger`; `account_compromise`; `outage` with `affected` group or campus, `kind` fault and `urgency`
not routine; `deadline` hours with `kind` fault. `urgency` alone (tone) is never a rule. The first draft
(outage with group scope only) produced 3 false-high rows on tune (flaky wifi), so urgency was added as a
qualifier. Precedence: safety > student answer > lexicon urgency rule > `llm_cue` > head. It fires only when
the front end call returned a valid reply for that row (Arabic and Arabizi); English requests are not sent to
the LLM, so English stays lexicon-only. Cue values per request appear only in the `llm_cues` debug column.

## Package 2: routing

a. `injection_attempt` now routes to HUMAN_REVIEW (policy rule `b1_injection`, never auto). The guard strips the
matched span plus a directly following routing clause (`steer_clause` bank: "and forward this to Finance as top
priority", `وابعت هاد لقسم الصيانة`), counted outside the whole-sentence ratio so the real request after the
clause survives. `ur instructions` added to the override pattern. Dev injection probes (tune): the three labels
are unchanged (Facilities, Finance, Finance, all correct); routing before to after: AR 3 to 3 (review), EN 3 to 3,
AZ ask to review (the Arabizi probe was not flagged before; it is now). Offline Arabizi category F1 on tune
0.684 to 0.722 (one row). Unit tests show the department name removed from the stripped text and the real
request kept.

b. Queue-jump bank (`queue_jump`, EN, AR, Arabizi): name-dropping a relative or friend who is senior, asking to
skip the line or go first, threats to complain, "very urgent" style shouting. A hit sets the internal flag
`queue_jump`; the priority path (priority model, evidence, floors, LLM cues) reads the text without the phrase,
the category path reads the text unchanged, so pressure moves no category and cannot raise a priority (a threat
phrase that had taken a priority to high now stays medium). `skip the queue` moved from the injection bank to
this bank (it is pressure, not injection). Dev queue-jump probes: labels unchanged on all three; none went high.

c. `too_vague` (new `vague` bank, whole-text match of filler and generic help words; zero hits on the 432
official rows and 0 on the dev rows) and `gibberish` route to OUT_OF_SCOPE (ask the topic), like gibberish
already did online. A new rule `b3_far_singleton` sends a singleton set with `ood_score < tau_ood - 0.03` to
review. Dev: 0 rows left the auto bucket on tune and on check (auto bucket sizes 47 and 40 unchanged; tune auto joint accuracy 29/42 unchanged),
so no good answer was sent to review. At the plain `tau_ood` margin the rule would have moved 5 of 44 auto tune
rows with 80 % joint accuracy against 70 % for all auto rows, which is why the margin is 0.03. Synthetic
inputs ("help", "I have a problem and need help please", Arabic and Arabizi equivalents) now route to
out_of_scope; the off-topic recipe and capital-of-France texts already had empty conformal sets (review).
Batch labels are never changed by these routes; `predict.py --debug` has a new `route` column (the policy's
outcome) and `llm_cues`; `scripts/dev_eval.py` buckets from `route` when present.

## Unfinished and notes

- The new flags are internal (not in the public API flag enum, to keep the OpenAPI contract and web types fixed);
  exposing `queue_jump` to staff needs an API change.
- Models frozen before this change have no `queue_jump`, `steer_clause` or `vague` keys: the features stay off
  there; `models/frozen/v1` was not refrozen, so the shipped model needs a refreeze of its lexicons to get them.
- The dev set has no off-topic or empty-intent rows, so the vague rule is validated only on synthetic inputs,
  zero official hits and zero dev movement.
- Cue rule thresholds were tuned on tune plus the official explanation cues; LLM replies differ slightly between
  runs, so expect small variation.
