## What C3 is

C1's recipe (rc4 weights recipe + the 447 model-panel rows, folds `cv_folds_aug.csv`, opus-mt training translations)
with one change: the 447 rows are marked `category_only` (config `config/rc5_c3.yaml`:
`model_reviewed_priority: false`, read by `train.py --toggles-file`). Category-only rows are used by the category
members (m2lr, m2proto learned prototypes, the category kNN index), the category conformal quantile and the
category-side thresholds. They are removed from: the priority members' training rows (m1, m2lr), the priority head
fit (OOF and freeze), the priority kNN index (a separate `train_priority` collection in `index/`; offline loading
uses it when present and still accepts the old 3-collection layout), the head temperature calibration, the priority
priors, and the priority conformal quantile (global and per language). Stage-B weights were already fixed
(D-016) and choices already used official rows only. The release guard is unchanged (`--include-model-reviewed` only
with `--out` outside `models/`).

```
python services/ai/train.py --out .tmp/rc5/C3 --report .tmp/rc5/cv_C3.json --include-model-reviewed \
  --toggles-file config/rc5_c3.yaml --folds .tmp/rc5/cv_folds_aug.csv --translation-cache .tmp/rc5/translations_opus.csv
```

Tests (`test_pool.py::test_category_only_rows_stay_out_of_every_priority_input`,
`test_p8_retrain_tools.py::test_category_only_rows_calibrate_category_not_priority`): (a) the priority training
inputs (soft-target expansion) of the C3 pool equal C0's official pool, while C1's differ by the extra row; (b) the
category inputs include the reviewed row; (c) the priority quantile ignores category-only rows, the category one does
not. ruff clean on the changed files (3 older E501 in the P8.1 test file remain), `mypy --strict` clean, unit tests
854 passed.

## A finding about C1 (corrects the P8.1 report)

The P8.1 report says C1's conformal calibration used official OOF rows only. It did not: `stage_b` calibrated both
quantiles on the whole pool (`n_calib` 879 = 432 official + 447 reviewed). Frozen quantiles:

| | q_category | q_priority | n_calib |
|---|---:|---:|---:|
| C0 | 0.543 | 0.586 | 432 |
| C1 | 0.805 | 0.792 | 879 |
| C3 | 0.805 | 0.586 | 879 (priority: 432) |

So C1's wider priority sets and doubled ask rate (our_test 0.13 to 0.27) come from calibrating on the noisier reviewed
rows. C3's priority quantile equals C0's exactly.

## Reading

C3 is a cleaner version of the reviewed-data idea: all of C1's category gain, none of its priority regression, and a
lower ask rate than C0. It is not a priority improvement: any priority gain C1 showed on OOF and dev came from the
reviewed rows' priority labels (and from the wider conformal calibration), and those labels are exactly what the
model panel disagreed on. D-016 still fails on the OOF category lower bound (0.000), so adoption would still need the
decision and the disclosure that the 447 rows are model-reviewed, not human-reviewed. The tie-break rule keeps C0 as
the simplest candidate unless the holdout separates them.
